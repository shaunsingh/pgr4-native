# PGR4 native renderer: architecture reference

This is the reference for how the native D3D12 renderer in `native/` works:
threads, data flow, every cache and the rule that keeps it valid, memory, cvars, and the frame
CSV. It describes master after the 2026-10-21 merges of TexturePerf, DrawCPU, HitchFix and
RenderThread (the render thread is on by default since 2026-10-21 23:20). The project log, the measurements
and the history behind each decision are in `the development notes` (sections under
`### Milestone 3 (M3)`) and `the development notes`. `docs/native-renderer-design.md` is the
original design study (FM2-ReGPU, ReXGlue integration, the choice of design A).

## What it is

PGR4 is statically recompiled by MissingThePixel/MTR-PGR4 on the ReXGlue SDK v0.10.0. Normally
the recompiled game's guest D3D library writes PM4 packets into a ring buffer, and ReXGlue's
Xenos plugin (`rexgpu-xenos.dll`, Xenia's D3D12 backend) replays them on a `GPU Commands` thread.
That thread emulates the Xbox 360 GPU (the Xenos).

Design A hooks the guest D3D library's own functions in the recompiled code. There are 197 of
them, listed in `src/d3d_surface.inc` and generated by `tools/scan_d3d_surface.py`. Each hook
first calls the original guest function, so the guest D3D state and the PM4 stream stay exactly
as before. Then, for the outermost draw, clear, resolve and Swap calls, it passes the call to the
`NativeRenderer`, which reads the Xenos register state the guest D3D left behind and records
D3D12 work itself.

Two modes:
- `--pgr4_native`: the native renderer runs beside the Xenos plugin and presents into its own
  debug window. Both render every frame. This is the mode the image oracles compare.
- `--pgr4_native_primary` (implies `--pgr4_native`): the native renderer presents into the
  game's window. The SDK patch `rexglue-native-primary.patch` adds `--gpu_skip_draws`, which the
  renderer sets at start-up. With it the Xenos command processor still parses the stream, runs
  fences, interrupts and `EVENT_WRITE_ZPD` (fake sample counts), but skips draws, copies, clears,
  shader loads and swaps. Its `GPU Commands` thread drops from ~98 % of a core to ~13 %.

## Threads

| Thread (SetThreadDescription name) | Created by | Does |
|---|---|---|
| `Main XThread` (guest) | the game | Runs the game. Hooks run here: tracker updates, then either the whole native path (render thread off) or only the capture step (render thread on) |
| `PGR4 native render` | `NativeRenderer` when `--pgr4_native_render_thread` (default true since 2026-10-21 23:20, owner's call; one of three race oracle captures still drops to 29.5-29.6 dB with it) | Replays captured commands into the modules; owns the command list, every D3D12 object and all module state |
| `PGR4 native untile` (1-4) | `TextureCache` (a quarter of the hardware threads, clamped 1-4: 4 on an i9-13900K, 2 on a Deck) | Untiles guest textures into upload memory |
| `PGR4 native pipelines` | `DrawRenderer` when `--pgr4_native_async_pipelines` (default on) | Creates PSOs, loads/stores them in the `ID3D12PipelineLibrary`, runs prewarm jobs |
| texture-heap `std::async` | `TextureCache::StartSpareHeap` | Creates the next 128 MB texture heap while the current one fills |
| window thread | `D3D12Device` | Owns the debug window or the child window over the game window |
| `GPU Commands` (SDK) | Xenos plugin | PM4 parsing; in primary mode only fences/interrupts |

Measured on the race (13900K): `Main XThread` ~98 % in every mode (the game itself fills it),
`PGR4 native render` 42-44 %, `GPU Commands` 13-15 % in primary mode, 98-99 % in Xenos mode.

## A frame, render thread on

1. Game thread, every flushing guest D3D call (draws, clears, resolves, Swap and a few internal
   ones; `IsStateFlushingFn` in `d3d_state.cpp`): `ReadDirtyMasks` before the original,
   `GuestStateTracker::AfterCall` after it. The tracker keeps a 0x5000-register file (VS/PS float
   constants 0x4000/0x4400, fetch constants 0x4800, bool/loop 0x4900, render state 0x2000+).
   It copies the register blocks the call flushed from the guest device's shadow, the window
   scissor, and, for draws, the bound shaders and their literal constants.
   Every write goes through `Put`/`Copy`, which compare with a big-endian mirror 16 registers per
   branch (SSE2) and set a changed-register bitmap.
2. Game thread, the outermost draw/clear/resolve/Swap (`OnHook` in `pgr4_d3d_trace.cpp`; a
   top-level `BeginVertices` is held until the next hooked call, after the game wrote its
   vertices): the capture step.
   - Draw: `ReadDrawState` (primitive, counts, index buffer, inline vertices, shader refs) and
     `DrawRenderer::Prepare`. Prepare does the shader lookup (`ShaderCache::Load` plus memos;
     an immediate VS's patched copy is read here while the tracker still holds it), the vertex
     and index copies into upload memory (`RequestRange`, page watch included) and the
     triangle-fan index conversion.
   - Clear: `RenderTargets::DecodeClear` (rects, colour, depth/stencil values, bound surfaces).
   - Resolve: `DecodeResolve` (arguments from the guest stack and parameter block).
   - Swap: `Presenter::ReadSwap` (the front buffer's fetch constant).
   - `TakeChanges` turns the changed-register bitmap into (register, value) pairs attached to
     the command. Commands go into batches of 256 (a Swap ends a batch).
3. Render thread: applies each command's register pairs to its own register file, then runs the
   module (`Draw(base, s, prep)`, `Clear`, `Resolve`, Swap). At Swap: present blit,
   `TextureCache::FinishUploads` (waits for the untile workers), `EndFrame` (close, execute,
   Present, fence), retirement of upload memory, the CSV row.
4. Pacing: at Swap F the game thread waits until the render thread finished Swap F-1, so the
   renderer is at most one frame behind. `hook_wait_us` in the CSV is that wait; it was 0 in every
   steady race window measured. Captures (`capture.request`) run their arming Swap and the
   captured Swap synchronously, so `HoldFullReadback` and the guest-memory read happen while the
   game thread is held in its Swap hook.

With `--pgr4_native_render_thread=false` every module runs on the game thread right after the
hook, as before the rthread merge. The only shared change is the tracker's change tracking.

## Coherency rules (what may be read late)

The Xenos plugin reads guest memory whenever its command processor gets to a packet, often a
frame after the game wrote it. In primary mode it signals fences almost at once, so the game can
reuse buffers sooner than on real hardware. The renderer therefore:
- Copies vertex and index data at hook time on the game thread (`RequestRange`). Dynamic buffers
  may be rewritten soon after the draw, and the copy must hold the draw-time data.
- Reads texture data late, on the untile workers, before the frame's command list is submitted.
  The page watch is armed before the read, so a write after it marks the texture stale again.
  Consequence: a texture the game rewrites every frame (`12B60000`, 256x512 R5G6B5) can show the
  next frame's contents.
- Reads shader ucode at capture time (`Prepare`), because immediate VS loads are patched copies
  in the push buffer.
- Takes Resolve/Clear/Swap arguments at capture time, because they live on the guest stack.
- Resolve dumps (`--pgr4_native_resolve_dump`) read guest memory from `Resolver::AfterSwap`,
  which now runs on the render thread; run dumps with the render thread off.

## Caches and memos, with what invalidates each

Every cache below lives on the thread that runs the module (the render thread when it is on),
unless noted.

| Cache | Key | Valid while | Where |
|---|---|---|---|
| Shader memo | last draw's (ucode address, size, immediate seq), then a 64-entry table keeping the first and last 8 ucode dwords | the ucode at that address is the same | draw.cpp (`LoadShader`/`Prepare`, game thread when the render thread is on) |
| `SelectModifications` memo | shader pair + the registers the selection reads (index count no longer part of it) | inputs equal | draw.cpp, 89 % hits |
| Translation memo | shader + modification | forever (translations are never freed) | draw.cpp |
| Ready-pipeline cache | key hash after depth-bias zeroing | pipeline ready | draw.cpp, 99 % hits, in front of `GetPipeline` |
| Pipelines | XXH3 of `PipelineKey` | never removed; `kCompiling`/`kReady`/`kFailed` | draw.cpp, async on `PGR4 native pipelines` |
| RT lookup memo | surface registers | equal | render_targets.cpp (16 entries) |
| `TextureCache::Get` memo | the 6 fetch dwords (1,024 entries, hashed) | `Unchanged(texture)`: not dirty (guest write) and no pending resolve | textures.cpp |
| `BindMemo` | (shader, the fetch constants it reads), 2-way set-associative, 2^11 sets, plus each shader's last entry checked first (87 % of hits) | `change_epoch` equal, or every bound texture `Unchanged`; shaders with a missing texture or more than the slot limit are not memoized | draw.cpp `bind_textures` |
| SRV memo | texture resource (not the fetch slot) | resource + view desc equal | draw.cpp |
| Sampler memo | hashed table of (fetch dwords, filter overrides) | equal | draw.cpp |
| `CachedCbv` (b0-b4) | last upload of each constant buffer, kept in CPU-cached upload memory | bytes equal (compared against the last upload itself) | draw.cpp |
| Valid-page bitmap | 4 KB guest pages mirrored into the shared-memory buffer | cleared by the page-watch callback on a guest write | draw.cpp (`RequestRange`) |
| Resolve targets | every subresource address `CopyResolved` looks up → textures there | `OnResolved(address)` marks those textures `resolve_pending` and bumps `change_epoch` | textures.cpp |
| Pipeline library | hash of description + bytecode | the driver accepts the library; otherwise it is rebuilt | `<cache_root>\pgr4-native\pipelines.d3d12lib` |
| Pipeline list | key (shader pointers replaced by ucode hash + modification) + shader ucode | header matches `sizeof(PipelineKey)` and `kPipelineKeyVersion` (2) | `<cache_root>\pgr4-native\pipelines.bin` |

`change_epoch` (textures.h) goes up on every guest write that marks a texture dirty, every
resolve into a texture, every upload and every creation. The fault thread increments it after
setting the dirty flag (acq_rel), so a memo that read the old epoch rechecks and sees the flag.

Bump `kPipelineKeyVersion` in draw.cpp whenever a `PipelineKey` field changes meaning, or old
`pipelines.bin` files will prewarm wrong keys.

## Memory

| Pool | Size | Notes |
|---|---|---|
| Shared memory buffer | 512 MB default heap | Mirror of guest physical memory for vertex/index fetch (raw SRV + UAV); pages copied on demand |
| Vertex upload | 16 MB blocks, 4 reserved at start-up | Game thread's when the render thread is on; recycled at the game thread's Swap from `gpu_frames_done` |
| Constant upload | 4 MB blocks, 12 reserved, CPU-cached (CUSTOM heap, write-back, L0) | Read back for comparisons, so write-combined memory would be slow |
| Texture upload | 32 MB blocks, 4 reserved | Untile workers write here; GPU copies into textures |
| Texture heaps | 128 MB each, bump-allocated, never freed (textures are never destroyed) | 4 KB placement where allowed, else 64 KB; the next heap is created in the background |
| Descriptor heaps | 65,536 views, 2,048 samplers | Bindless; first 3 table entries are null 2D-array/3D/cube views |

Upload memory is write-combined unless noted. Never read it back on the CPU: on 2026-10-21 a
per-row conversion that read the destination cost ~55 ns per byte (14 ms per frame for one
256x512 texture; 98 ms for a 1280x720 depth upload). `UntileTexture` now converts in a cached
scratch row.

## Frame CSV columns

Always: `frame, draws, clears, resolves, state_fail, draw_us, clear_us, resolve_us, swap_us,
us_per_draw, frame_ms, host_draws, skipped, unsupported, failed, pso_created, upload_kb,
textures, textures_missing, front_buffer`. With the render thread: `hook_us` (game-thread time
in the On* calls), `hook_wait_us` (waiting for the render thread at Swap), `reg_writes`
(register values replayed). Then `swap_untile_us, swap_submit_us, swap_present_us, swap_fence_us,
hook_max_us, watch_faults, gpu_prev_ms, copy_batches, watch_arms, watch_arm_pages, t_ms,
hash_pages, hash_copies`, `pso_pending` (draws dropped while their pipeline compiles) and
`pso_wait_us` (time draws waited for their pipelines in a burst of new ones), `held` (1: the
frame was not presented, it skipped draws in such a burst), `tex_stale` (texture bindings
for draws the game queued before a newer write of the texture's memory; with
`--pgr4_native_texture_capture_order` they keep the older data). With
`--pgr4_native_luma_probe`, last: `luma_frame` and `luma_{top,mid,low}_{0..3}` (mean brightness
0-255 of each quarter, left to right, of the front buffer rows at 10, 40 and 80 % of its height,
for the frame `luma_frame`).

With `--pgr4_native_profile`, also:
- `st_<stage>_us` for each stage in `profile.h`: `read_state, shaders, setup, rt_bind,
  translate, pipeline, textures, sysconst, pack, vertices, cbv, record, track, imm_vs, tex_miss,
  tex_get, tex_srv, guest_d3d`, plus `cap_shaders, cap_vertices, cap_record` (game-thread
  capture) with the render thread. `tex_miss`, `tex_get` and `tex_srv` are sub-timers inside
  `textures`. `guest_d3d` is the time inside the original guest D3D functions at the outermost
  hook, including nested tracking. These four are left out of the stage sum.
- `track_calls, tex_memo_miss, tex_created, tex_create_us, tex_uploads, tex_upload_kb,
  tex_upload_us, tex_untile_us` (worker CPU), `tex_resolved_copies, tex_copy_resolved_us,
  tex_resolved_aliases, srv_lookups, srv_created, samplers_created, bind_hits, bind_misses`.
- Counters (`profile.h` `kCounterNames`): `bind_hit, bind_mru, bind_miss_empty,
  bind_miss_fetch, bind_miss_tex, bind_nomemo, get_miss_fetch, get_miss_changed, srv_memo_hit,
  tex_upload_skip`.

The log prints a `PGR4 native: frames N | per frame ...` line and, profiled, a `profile:
ns/draw ...` line every `pgr4_d3d_stats_frames` frames, and a `draw diag` line (memo hit rates,
ranges, CBV uploads per draw) every 300 frames.

## Where the time goes (2026-10-21)

Race, uncapped, primary, i9-13900K + RTX 3090, profiled, last 600 frames (`int1-warm`, master
0233a0f before the rthread merge, 2,345 draws per frame):

| Stage | ns/draw | Stage | ns/draw |
|---|---|---|---|
| textures | 218 (of it `tex_miss` 104, `tex_get` 80) | track | 115 |
| cbv | 175 | record | 113 |
| vertices | 120 | pack | 50 |
| shaders | 46 | pipeline | 41 |
| setup | 39 | rt_bind | 39 |
| sysconst | 24 | translate | 19 |
| read_state | 19 | | |

Frame time on the same tree, unprofiled, the 40 s after the race mark: primary 10.00 ms
(100 fps), Xenos-only 7.69 ms (130 fps). On the merged rthread exe (`native-DrawPerf`, 670fced):
render thread on 7.76 ms (128.9 fps), off 10.46 ms (95.6 fps), Xenos only 7.95 ms (125.8 fps);
game-thread native cost with the thread on ~460 ns per draw (track 247, cap_record 78,
cap_vertices 71, cap_shaders 42, read_state 21), render thread 43 % of a core.

The remaining costs are mostly D3D12 calls (root CBV binds about 2.4 per draw, barriers for
inline vertices, the draw itself) and the 62 resolved-image copies per frame (~115 µs). The
guest's own work is ~8 ms per frame on this CPU and sets the floor for either mode.
